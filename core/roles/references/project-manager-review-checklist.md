## Project Manager Review Checklist

This reference checklist provides operational delivery coordination, multi-agent capacity planning, FinOps spend governance, and regulatory milestone verification criteria for project management to meet SOTA 2026–2027 standards. It establishes non-negotiable verification gates across probabilistic delivery estimation, multi-agent DAG governance, token budget envelopes, Specification-Driven Development (SDD) enforcement, review queue dwell-time management, commit provenance tracking, and rollback readiness.

### 1. Probabilistic Delivery Estimation & Variance Modeling (`PROBABILISTIC-ESTIMATION LOCK`)
- **Statistical Confidence Percentiles (P85 Target)**:
  - delivery milestones involving AI-assisted development or stochastic agentic workflows avoid brittle single-point date commitments
  - schedules model statistical delivery distributions (Monte Carlo simulations or three-point PERT estimations) committing to P85 confidence envelopes with documented variance bounds
- **Buffer & Variance Contingency**:
  - explicit schedule buffers inserted between dependent phases to absorb model regression debugging and evaluation cycles

### 2. Multi-Agent DAG Capacity & Orchestration Governance (`AGENT-CAPACITY LOCK`)
- **Blended Human-Agent Capacity Planning**:
  - sprint and release plans account for concurrent agent workload capacity, LLM provider rate limits (TPM / RPM), and token quotas alongside human engineering bandwidth
  - agent delegation graphs reviewed to ensure critical paths do not bottleneck on single rate-limited models or unavailable specialized agents

### 3. Token FinOps, Cost Allocation & Spend Governance (`TOKEN-FINOPS LOCK`)
- **Cost-Per-Task Ceilings & Envelopes**:
  - every automated agent phase defines an explicit financial ceiling (maximum allowable dollar spend per feature or task)
  - token burn rates monitored daily; programmatic circuit breakers trip and pause workflows if spend velocity exceeds projected baseline by $>25\%$
- **FinOps Attribution & Chargeback**:
  - token and compute expenditures tagged by initiative, team, and repository to maintain transparent cost attribution

### 4. Specification-Driven Development (SDD) & Code Churn Defense (`AI-DEBT & SPECIFICATION LOCK`)
- **Contract-First Engineering Gates**:
  - engineering tasks must possess approved specification contracts (`feature-ticket.json`, `api-contract-spec.json`, or architecture ADR) before implementation begins; "prompt-and-pray" implementation without verified contracts rejected
- **Code Churn & Duplicate Bloat Auditing**:
  - automated repository metrics inspect pull requests for AI-generated code bloat, hallucinated dependencies, or excessive line churn; PRs exceeding churn thresholds flagged for architectural review

### 5. Reviewer Fatigue Mitigation & Approval Queue Dwell Time (`ANTI-FATIGUE & DWELL-TIME LOCK`)
- **Approval Optimization**:
  - human approval gates placed strictly on high-impact, risky, or irreversible actions; low-risk read-only steps run autonomously to prevent human reviewer burnout
- **Dwell-Time SLA Tracking**:
  - human review queue dwell time tracked; review bottlenecks exceeding 4 business hours escalated to prevent stalling downstream agent execution graphs

### 6. Commit Provenance Tracking & Regulatory Governance (`COMMIT-PROVENANCE LOCK`)
- **Git Commit Provenance Tagging**:
  - commits generated by AI agents must record machine-readable provenance metadata in commit trailers (`Co-authored-by: <agent-id> <model-version>`)
- **Regulatory Timeline Compliance (`AI-COMPLIANCE LOCK`)**:
  - project plans track live EU AI Act milestones: August 2026 transparency (Article 50) and GPAI governance gates enforced prior to release; Annex III high-risk compliance scheduled against December 2027 deadlines

### 7. Critical Path Dependencies & Uncommitted Blocker Defense
- **Explicit Cross-Team Dependency Commitments**:
  - all external dependencies (platform APIs, shared services, infrastructure provisioning) validated as committed deliverables with named owners before locking sprint plans
  - uncommitted or assumed dependencies flagged as high-risk delivery blockers

### 8. Rollout Windows, Staging Verification & Rollback Playbooks
- **Gated Deployment Windows**:
  - release schedules include dedicated staging verification windows and automated canary evaluation periods prior to full traffic cutover
  - comprehensive rollback playbooks with verified recovery time objectives (RTO $\le 15\text{min}$) documented for every release

### 9. Project Governance & Status Reporting Standards (`STATUS-TRANSPARENCY LOCK`)
- **Deterministic Milestone Tracking**:
  - progress tracking driven by machine-verifiable deliverables and test passes, never speculative percentage estimates
  - blockers, dependency delays, and unverified assumptions exposed immediately in daily status summaries
- **Capacity Re-Balancing**:
  - workload re-allocation triggered dynamically when agent burn rates or human review dwell times violate operational SLAs

### 10. Operational Failure Modes & Escalation Triggers
- **Agent Stalling Escalation**:
  - automated workflows idling or looping without progress for $>30\text{min}$ trigger incident notifications to on-call coordinators
  - budget threshold breaches immediately pause batch executions pending human authorization
